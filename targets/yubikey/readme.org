* yubikey

Enable YubiKey devices and the smartcard stack.

The target covers three separate YubiKey applications. Each one uses a
different channel to the key:

| Application  | Used for                       | Channel                   |
|--------------+--------------------------------+---------------------------|
| FIDO2 / U2F  | Google, GitHub, browser logins | =/dev/hidraw*= (direct)   |
| OpenPGP, PIV | gpg keys, ssh, certificates    | =pcscd= (CCID smartcard)  |
| OATH         | TOTP codes                     | =pcscd= (CCID smartcard)  |

The browser never goes through =pcscd=. This matters for troubleshooting.
A gpg session that holds the smartcard does not block a Google login.

** What it installs

- =pcsclite= and =ccid=: the PC/SC daemon and the CCID reader driver
- =pcsc-tools=: =pcsc_scan= for diagnostics
- =yubikey-manager=: the =ykman= command line tool
- =yubikey-personalization=: =ykpersonalize= and the =69-yubikey.rules= udev rules
- =yubico-authenticator-bin=: the desktop TOTP application
- =pam-u2f= and =libfido2=: FIDO2 and U2F support

** What it enables

The post hook enables =pcscd.socket= and reloads the udev rules.

** Device access

The packages supply the udev rules. The rules use =uaccess=, so the logged-in
user gets access to the device through an ACL.

** Check the setup

#+begin_src sh
systemctl status pcscd.socket
pcsc_scan                 # smartcard side
ykman info                # which applications are enabled
ykman fido info           # FIDO2 PIN state
fido2-token -L            # which hidraw node the browser will use
gpg --card-status         # OpenPGP side
#+end_src

=fido2-token -L= must print a line. If it prints nothing, the browser cannot
see the key either.

* Google access in Firefox

Firefox talks to the key over =/dev/hidraw*= with its own FIDO2 stack. Firefox
114 and later support FIDO2 security keys and passkeys on Linux. The native
Arch =firefox= package needs no extra configuration.

Google offers two ways to use the key. Pick one, or use both:

- *Passkey*: replaces the password. The credential lives on the key. A FIDO2
  PIN is required.
- *Security key*: a second factor after the password. No PIN is required.

** 1. Set a FIDO2 PIN

A passkey needs a FIDO2 PIN. Check the current state first:

#+begin_src sh
ykman fido info
#+end_src

If the output reports a PIN, a PIN is already set. To set a new PIN, run:

#+begin_src sh
ykman fido access change-pin
#+end_src

The PIN is 4 to 8 characters. It is not the OpenPGP PIN and it is not the PIV
PIN. Three separate PINs live on one key.

*Warning*: Do not run =ykman fido reset=. The command deletes every FIDO2
credential on the key. Every site that uses the key for login locks you out.

** 2. Register the key with Google

1. Plug in the key.
2. Open Firefox.
3. Go to [[https://myaccount.google.com/signinoptions/passkeys][myaccount.google.com/signinoptions/passkeys]].
4. Select *Create a passkey*, then *Use another device*.
5. Enter the FIDO2 PIN when Firefox asks for it.
6. Touch the gold contact on the key when it blinks.
7. Name the credential. Use the serial number from =ykman info= in the name.

For a second factor instead of a passkey, go to *Security*, then *2-Step
Verification*, then *Security key*, and follow the same touch prompt.

*Wait 7 days.* Google holds a new security key for 7 days before it works at
sign-in. This is an anti-hijack delay. Keep the old second factor until the
new key works.

** 3. Sign in

1. Enter the Google address.
2. Select *Use a passkey* or *Use your security key*.
3. Enter the FIDO2 PIN in the Firefox dialog.
4. Touch the key.

Firefox shows a native dialog, not a web page. The dialog asks for the PIN
first and for the touch second.

** Troubleshooting

*Firefox shows no prompt at all.*
Check that =fido2-token -L= lists the key. If the list is empty, the udev
rules did not apply. Re-run the post hook:

#+begin_src sh
caifs add -d targets -h yubikey
#+end_src

Then unplug the key and plug it in again. A udev reload does not fix a device
that is already connected.

*Firefox reports that the key is not usable.*
Check that FIDO2 is enabled on the key:

#+begin_src sh
ykman info
#+end_src

=FIDO2= must show =Enabled= for =USB=. To enable it, run
=ykman config usb --enable FIDO2=.

*Firefox asks for a PIN that you never set.*
The site requested a passkey. Set a FIDO2 PIN with
=ykman fido access change-pin=, or register the key as a second factor
instead.

*The PIN is wrong 8 times.*
The key blocks the FIDO2 application. Only =ykman fido reset= unblocks it,
and that reset deletes every credential. Count the attempts.

*Firefox is a Flatpak or a Snap build.*
The sandbox hides =/dev/hidraw*=. Use the native Arch =firefox= package. This
target assumes the native package.

*The key works in Firefox but =gpg --card-status= fails.*
This is the =pcscd= side, not the browser side. Read the =gpg= section below.

* SSH keys stored on the key

Carry the key to any machine and get SSH access there. The private key never
leaves the YubiKey. A stolen laptop leaks nothing.

This uses a FIDO2 *resident key*, also called a discoverable credential. The
YubiKey stores the key handle, so no file on disk is necessary.

Requirements:

- YubiKey firmware 5.2.3 or later for =ed25519-sk=.
- OpenSSH 8.2 or later on the client.
- A FIDO2 PIN. See the Google section above.

** 1. Decide: touch only, or touch plus PIN

This choice sets how the key feels every day. Make it before you generate.

| Option               | Cost per connection | Protects against                 |
|----------------------+---------------------+----------------------------------|
| Touch only           | One touch           | Theft of the laptop alone        |
| =-O verify-required= | PIN *and* touch     | Theft of laptop and key together |

=-O verify-required= demands the PIN on *every single signature*. No cache
exists. A =git fetch= asks for the PIN. A loop over ten servers asks ten times.

It also breaks agent use unless an askpass helper is installed. The agent has
no terminal, so it cannot prompt for the PIN on its own.

*Use touch only.* The PIN still guards the part that matters. A thief with the
key alone cannot copy the credential to a new machine, because =ssh-add -K=
and =ssh-keygen -K= both demand the PIN. Touch only keeps the daily cost at
one touch.

Add a second =verify-required= key later if one target needs the extra step.

** 2. Create the key, once

#+begin_src sh
ssh-keygen -t ed25519-sk -O resident \
    -C "yubikey-<serial>" -f ~/.ssh/id_ed25519_sk
#+end_src

=-O resident= stores the credential on the YubiKey. This makes the key
portable. Without it, the key works only on machines that hold the handle file.

Enter the FIDO2 PIN, then touch the key. Leave the passphrase empty. The
passphrase protects the local handle file, not the secret.

Two files appear:

- =~/.ssh/id_ed25519_sk=: the *key handle*, not a private key. It names the
  credential on the YubiKey. It is useless without the key.
- =~/.ssh/id_ed25519_sk.pub=: the public key. Type =sk-ssh-ed25519@openssh.com=.

The private key stays inside the YubiKey. No command extracts it.

A resident key uses one of the 25 credential slots on firmware 5.4. Firmware
5.7 and later have 100 slots. Check the count with =ykman fido credentials list=.

*** More than one key

To keep separate credentials, for example work and personal, give each one a
different application string:

#+begin_src sh
ssh-keygen -t ed25519-sk -O resident -O application=ssh:work -f ~/.ssh/id_work_sk
#+end_src

The application string must start with =ssh:=. Use =-O user=<name>= to store
several keys under one application string.

** 3. Use the key on any other machine

Plug in the key and run:

#+begin_src sh
ssh-add -K
#+end_src

This loads every resident key from the YubiKey into the agent. It writes no
file to disk. Enter the FIDO2 PIN when it asks.

Now ssh works. Every connection asks for a touch.

The agent forgets the key when the agent stops. Unplug the key and the
signature fails. Nothing remains on the borrowed machine.

If the machine has no agent, write the handle files to the current directory
instead:

#+begin_src sh
ssh-keygen -K
#+end_src

Delete those files before you leave.

** 4. Register the public key

Print the public key:

#+begin_src sh
ssh-add -L
#+end_src

The line starts with =sk-ssh-ed25519@openssh.com=. Add it to:

- GitHub: Settings, then SSH and GPG keys
- GitLab: Preferences, then SSH Keys
- A server: append the line to =~/.ssh/authorized_keys= on that server

** 5. The one hard limit: old servers

An =sk-ssh-ed25519= key needs OpenSSH 8.2 or later on the *server*. An older
=sshd= rejects the key type. It does not fail with a clear message. It reports
a normal permission denial.

Check a server before you rely on the key:

#+begin_src sh
ssh -v <host> 2>&1 | grep "remote software version"
#+end_src

GitHub, GitLab, and Bitbucket all accept these keys. A Debian 10 box or a
CentOS 7 box does not.

*Fallback for an old server*: use PIV with PKCS#11 instead. PIV presents a
normal RSA or ECDSA key, so every =sshd= accepts it. The =opensc= package
supplies the module:

#+begin_src sh
ssh -I /usr/lib/pkcs11/opensc-pkcs11.so <host>
ssh-add -s /usr/lib/pkcs11/opensc-pkcs11.so    # load into the agent
#+end_src

PIV needs setup first. The PIV application on this key still holds the factory
PIN, PUK, and management key.

** 6. This machine needs an IdentityFile line

=targets/ssh/config/.ssh/config= sets =IdentitiesOnly yes= for =Host *=. With
that setting, ssh offers only the identities named in the config. It ignores
the extra keys in the agent.

Name the public key in the config so ssh finds the agent key:

#+begin_src
Host *
  IdentityFile ~/.ssh/id_ed25519_sk.pub
#+end_src

The =.pub= file is correct here. Ssh reads the public half and asks the agent
for the signature.

This applies to this machine only. A borrowed machine has no such config, so
=ssh-add -K= is enough there.

** 7. Enroll a second key first

A resident key on one YubiKey is a single point of failure. Lose the key and
you lose the access.

1. Create the same kind of resident key on a second YubiKey.
2. Add both public keys to every service and every =authorized_keys= file.
3. Test the second key before you remove the old software keys.
4. Store the second key in a different physical place.

** Housekeeping

#+begin_src sh
ssh-add -L                              # what the agent holds now
ykman fido credentials list             # what the key stores, needs the PIN
ykman fido credentials delete <id>      # free a slot
ssh-add -D                              # clear the agent
#+end_src

* OATH TOTP

Use the desktop application =yubico-authenticator=, or the command line:

#+begin_src sh
ykman oath accounts list
ykman oath accounts code <name>
#+end_src

OATH goes through =pcscd=. If =scdaemon= holds the card, =ykman oath= fails.
The =pcsc-shared= setting in =scdaemon.conf= prevents this.

* gpg

=config/.gnupg/scdaemon.conf= tells =scdaemon= to go through =pcscd=. If
=scdaemon= uses its own CCID driver while =pcscd= runs, the two fight for the
reader.

If the card stops responding, drop the =scdaemon= session:

#+begin_src sh
gpgconf --kill scdaemon
gpg --card-status
#+end_src
